Stockflow – Order & Sales Core Refactor

A frozen, execution-ready plan to refactor the core Order + Sales workflow. This document is visual-first, scope-controlled, and designed to be followed without debate.

1. Why This Refactor Exists

  • Sales logic was previously tied to roles (salesman vs owner).
  • This breaks when building a product for multiple business types.
  • We are resetting the core so Stockflow can support offline + online + hybrid businesses.

Decision: Sales become role-neutral facts. Orders become first-class intent.

2. Core Mental Model (Locked)

Intent

Orders

Conversational, editable, operational. Used for packaging, courier, and tracking.

Fact

Sales

Final invoice. Created only when delivery succeeds.

Events

Payments

Multiple entries. Partial, advance, COD — all allowed.

3. Identifiers (No Confusion Rule)

  • Order No → Operational reference (packaging, courier, calls)
  • Invoice No → Accounting reference (sales only)
  • Once a sale exists, the UI and print must show both.

4. Order Lifecycle & Delivery States

Draft
Placed
Packaging
Out For Delivery
Delivered
Returned
Cancelled

All transitions are manual now. Automation can be layered later.

5. Real Operator Flow (20 Facebook Orders)

  1. Orders arrive in Facebook messages.
  2. Each confirmed customer → Create Order in Stockflow.
  3. Status → Placed (inventory reserved).
  4. Status → Packaging → Print Order Invoice.
  5. Status → OutForDelivery (hand to courier).
  6. Courier feedback:
    • Delivered → Serve Order → Sale created.
    • Failed → Returned → Inventory released.

6. Serve Order = Atomic Operation

  • Create Sale
  • Generate Invoice No
  • Create sales_details
  • Copy payments + add COD if needed
  • Deduct inventory
  • Link order → sale

7. What We Explicitly Do NOT Build

  • Courier API automation
  • Settlement & profit accounting
  • WooCommerce sync
  • Role & permission system
  • Multi-tenant platform logic

These are future layers. Not part of this refactor.

  • Orders can be taken from Facebook chats
  • Packaging + order invoice works
  • Courier delivery finalizes sale
  • No role-based logic in sales
  • Flow explainable to owner in 2 minutes
